CLICKTOOLS — PACOTE COMPLETO DO PROJETO
=======================================

PROJETO: clicktools (https://clicktools.vercel.app)
ESTE PACOTE É DO CLICKTOOLS. "CLICK & GRUDA" É O NOME/IDENTIDADE
COMERCIAL QUE APARECE EM PÁGINAS DA APLICAÇÃO, NÃO O NOME DO REPOSITÓRIO.

ATENÇÃO: CONFLITOS DO GITHUB DESKTOP
-------------------------------------
Se o GitHub Desktop mostra "Resolve conflicts before Merge", NÃO adianta
apagar os arquivos e extrair este ZIP na pasta antiga: o estado do Git
fica guardado no diretório .git e os commits de origem podem divergir.

COMO INSTALAR EM UMA CÓPIA LIMPA (SEM MERGE)
--------------------------------------------
1. Na janela de conflitos do GitHub Desktop, clique em "Abort merge".
   Não clique em "Continue merge".
2. Preserve a pasta antiga como BACKUP. Não apague nada dela.
3. No GitHub Desktop, use File > Clone repository e selecione "clicktools".
   Para Local path, escolha UMA PASTA NOVA E VAZIA, como C:\clicktools-limpo.
   Não clone em cima da pasta antiga.
4. Depois de clonar, abra a pasta nova pelo GitHub Desktop
   (Repository > Show in Explorer).
5. Extraia os ARQUIVOS deste ZIP na RAIZ da pasta nova (aquela com package.json),
   substituindo os arquivos. NÃO coloque tudo dentro de uma subpasta extra.
6. Mantenha a pasta .git que veio do CLONE NOVO. Não copie .git da pasta antiga.
7. Se seu sistema precisar de .env ou .env.local, copie APENAS esses arquivos
   da pasta antiga para a pasta nova, sem colocar segredos no Git.
8. GitHub Desktop > Changes: revise os arquivos; depois faça Commit to main
   e Push origin. NÃO execute Pull origin na pasta antiga com histórico divergente.
9. Confira o resultado do deploy na Vercel. Faça backup do banco antes
   de aplicar qualquer mudança do Prisma.

AVISOS IMPORTANTES
------------------
- Este ZIP não inclui .git, .env ou node_modules.
- O ZIP NÃO resolve divergências do Git automaticamente; o procedimento de
  clone limpo é justamente para não reutilizar o histórico local conflitante.
- Alterações que só existam na pasta antiga e não no remoto ou neste ZIP
  podem ficar de fora. A pasta antiga deve continuar guardada como backup.
- Não foi possível executar build Next.js completo aqui por dependências
  incompletas; apenas a análise sintática TS/TSX foi realizada anteriormente.
